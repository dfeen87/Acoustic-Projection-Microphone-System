## State, trust and component contracts

* Failed incoming registration preserves SQLite state; generated identity conflicts cannot replace existing identities.
* Native terminal rejection preserves status/history; invalid projection evidence does not enter delay indexing.
* Startup validates dependency construction before acquiring tasks, and exceptional exit releases both services.
* Malformed telemetry leaves the last valid cache intact without extending freshness. Stale or absent native evidence remains offline.
* The launcher, backend and ASGI server now have an explicit client-provenance boundary; callers cannot supply identity evidence through proxy headers.
* Translation and signaling reject ambiguous/nonfinite/invalid-Unicode JSON. Backend translation parsing/decoding failure returns 502; invalid signaling text closes 1008. Native translation returns an initialized failure result. Peer-ID exhaustion returns 503 and invalid polling cursors return 422.
* The existing opt-in API-key mode is preserved. An unset key is not a hardened Internet deployment. WebSocket shared-token membership does not establish tenant isolation.

API diagnostics, profiles and calibration routes still expose prototype mock state. Their calibration-valid flag is not evidence from native hardware. Native async methods capture their owning object: callers must keep engine/system/adapter objects alive until their futures complete and coordinate lifecycle/configuration access. This pass does not claim destructor/async races or mutable calibration/profile access are universally safe. Installed translation callers must explicitly provide deployed bridge/model paths; checkout-relative defaults do not establish relocatable runtime inference.

## Pre-merge signaling compatibility follow-up

The GitHub review finding is valid. The later dashboard implementation in
`frontend/ui/APMDashboard.jsx` deliberately keeps `apm-lobby` membership and
generates independent `session-<timestamp>` call IDs. Commit `55e9a41` introduced
that persistent lobby behavior on 2026-04-22, after the older documents requiring
room/session equality. `WSSignalingClient` joins with `roomId` and sends subsequent
call metadata unchanged. The pre-hardening active standalone endpoint routed by
the socket's joined room without requiring session equality.

Pass A's equality check therefore conflated routing authorization with call
correlation. Its test used `sessionId = "room"`, masking the actual client
regression. The correction replaces only that equality with the existing
nonblank-string identifier policy when `sessionId` is supplied. Matching room
and session IDs remain valid; absent session metadata retains its prior behavior.
Invalid session metadata is dropped, while malformed JSON/protocol requests still
close with policy code 1008 where previously enforced.

Regression evidence was recorded before the correction:
`test_lobby_call_session_is_independent_of_routing_room` and the updated
`test_join_relay_retry_and_disconnect_contract` failed because `session-123`
was not the joined room. The first regression run had **14 failed / 17 passed**.
Receiver pings bound the assertions without hanging when a relay is dropped.
The final suite additionally retains the original equal-ID case.

The endpoint regressions exercise the shared ASGI `/ws` entrypoint, strict decoder,
join authentication and hub together. All six dashboard message types are routed
with either omitted or matching `roomId`; a peer in another room receives none.
Direct relay tests additionally prove a session ID named after another room
cannot select it, explicit cross-room routing and unjoined senders are blocked,
sender identity is overwritten without mutating the input, and `toPeerId` still
does not replace the existing within-room broadcast semantics. Nine malformed
session-ID domains are rejected; missing/wrong tokens remain rejected and the
correct configured token works with independent lobby sessions.

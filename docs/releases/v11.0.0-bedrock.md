# 11.0.0 — BEDROCK engineering report and release notes

Date: 2026-10-07. Previous current release: 10.1.0.

The existing architecture is preserved. This release strengthens the guarantees
underneath it: numerical validity, state integrity, truthful dependency status,
authorization boundaries and executable CI coverage. It does not certify an
acoustic product, install inference models, or publish a release.

## 1. Repository architecture understood

The C++20 library has a lightweight `APMCore` facade, a complete `APMSystem`
pipeline (beamforming, echo cancellation, suppression, feedback, VAD,
translation, projection), and a separate two-microphone smartglasses DSP engine.
The native executable owns capture queues and TCP monitoring. Public headers
under `include/apm` and the installed CMake target form the SDK interface.

Python FastAPI owns control endpoints, SQLite peers/sessions/metadata,
telemetry ingestion, intent handling and WebSocket signaling. React supplies
the dashboard; the Node launcher owns Python startup and the dashboard proxy.
UDP native signaling and Python discovery remain prototypes, separate from
the WebSocket protocol. Native key/value profiles and temporary translation
WAV files are additional persistence boundaries.

CMake feature flags select local translation, encryption and TFLite. FFTW,
libsodium and PortAudio are discovered system libraries; local translation
requires a Python bridge plus separately provisioned ML dependencies/models.
The optional intent provider uses an external key; a local fallback remains.
SDK, TGZ packaging, Docker and Windows installer metadata are separate delivery
surfaces. Existing architecture specifications, manifest, tests, workflows and
historical release documentation were examined before implementation changes.

## 2. Important invariants identified

Classification describes the previous baseline; tests in the last column now
enforce the named corrected behavior unless explicitly limited.

| Behavior | Architectural invariant | Previous enforcement / coverage | Current proof |
|---|---|---|---|
| Core initialization | A rejected configuration preserves valid state | Contradicted; ordinary initialization tested | `BedrockCore.FailedReinitializationPreservesValidState` |
| Recursive audio filter | Finite overload cannot poison future frames | Assumed; extreme finite recurrence untested | `ExtremeFiniteSamplesDoNotPoisonFilter` |
| Frames / full pipeline | Validate dimensions, rate and numerical domain before mutation | Partial checks; malformed boundary untested | `BedrockFrame`, `BedrockPipeline` |
| Smartglasses construction | Sanitize FFT/configuration before allocating dependent buffers | Contradicted; negative FFT untested | `BedrockSmartglasses` |
| Output aliasing | Consuming input must precede overwriting aliased output | Contradicted; untested | `OutputMayAliasInputWithoutDestroyingSpeech` |
| Calibration / profile load | Validity requires finite, complete evidence | Assumed; happy path covered | `BedrockCalibration`, `BedrockProfiles` |
| PTT shutdown | Shutdown leaves transmission inactive | Contradicted; reinitialization untested | `BedrockPtt` |
| Native call callbacks / shutdown | Observers read committed state; worker stop flag is synchronized | Contradicted; callback reentry and shutdown race untested | `BedrockSignaling` under ThreadSanitizer |
| Native session reads | A returned value survives later map mutation | Assumed raw-pointer lifetime | Owned snapshot regression in `BedrockSignaling` |
| Audio dependency | Unavailable driver cannot claim capture | Contradicted by stub | Conditional `BedrockAudio` and expected-failure CTest |
| SQLite identity / incoming retry | One transaction establishes one identity/effect | Object locks insufficient across instances | Concurrent independent-instance pytest regressions |
| Session transitions | Terminal states cannot revive; retries preserve history | Contradicted; happy paths covered | Storage and API BEDROCK regressions |

| WebSocket relay | Membership owns provenance and routing | Active standalone handler bypassed shared hub | Eight signaling regression cases |
| Telemetry | Malformed evidence cannot replace valid measurements | Partial parsing could mutate cache | Parameterized malformed-record tests |
| Translation response | Only complete JSON with boolean success and text is evidence | Hand parser accepted malformed success/trailing data | Native bridge and API malformed-output tests |
| Functional runner | Failed startup fails the test process | Startup exceptions could produce success exit | Deliberately missing Python startup check |
| Release testing / SDK | Assertions execute and installed headers compile | Release assertions disabled; install paths broken | CTest Release, independent SDK consumer, TGZ |

## 3. Previously implicit invariants

State must remain valid when initialization or input validation fails. Caller
configuration must remain an argument rather than shell syntax. Terminal
sessions must retain their history; retries must not refresh expiry. Telemetry
source and readiness flags must describe actual evidence and dependencies.
Authorization and signaling provenance must be established by the component
that owns them. These requirements follow from the existing state machines,
normalized PCM interface, monitoring fields and optional-dependency design.

## 4. Untested invariants discovered

Missing coverage included NaN/infinity and finite extreme values, FFT dimensions
before allocation, aliased buffers, absent calibration evidence, malformed
profiles, callback reentry, independent SQLite connections, repeated incoming
registration, terminal acceptance, forged forwarded headers, room injection,
malformed translation results and startup failure. The API smoke runner caught
assertions and returned false values that pytest did not treat as failures.
The Node runner also did not reliably fail failed startup. These were test
enforcement defects, not proof that every previously tested DSP path was wrong.

## 5. Confirmed defects and corrections

Failing regressions were recorded before the corresponding corrections.
Native callback reentry also reproduced a timeout/deadlock. The invariant table
identifies the contract justifying each significant change.

* Core initialization now prepares buffers before commit; finite overload is
  normalized before recursive filtering; uninitialized translation is rejected.
* Frame dimensions and full-pipeline inputs are validated before indexing or
  mutation. Process/reset share a mutex. Invalid smartglasses configuration is
  sanitized before allocation, and alias-safe input consumption is explicit.
* Calibration requires valid observations. Profile parsing consumes whole
  finite values, validates booleans and domains, rejects duplicate fields and
  requires measurement fields when calibration claims validity.
* PTT shutdown commits IDLE. Native call state callbacks run after unlock and
  index updates; reads return owned snapshots. Active-call admission is checked
  under the session lock. An atomic stop flag synchronizes shutdown with both
  workers, which stop before socket closure. ThreadSanitizer reproduced the
  previous plain-boolean data race before this correction.
* Missing PortAudio returns inactive/failure. Configuration is checked before
  hardware startup; inspected callback guards handle null buffers and exceptions.
  The executable returns failure and joins its worker when capture cannot start.
* SQLite connections close explicitly; identity and incoming registration use
  write transactions. Missing peers cannot create ordinary sessions. State
  transitions reject stale/nonfinite timestamps and terminal revival.
* Dashboard loading no longer creates a bearer credential. API exemptions are
  exact; client identity comes from the ASGI-resolved address. IPv4 input is
  validated, stable identities cannot be deleted, and API responses use committed
  storage state. Incoming node sessions are visible to the dashboard.
* Shared WebSocket handling enforces token, shape, membership and sender
  provenance; it snapshots broadcasts, removes dead sockets and cancels idle
  heartbeat tasks. The standalone app mounts this same handler.
* Telemetry validates a complete candidate before replacing its cache and uses
  monotonic freshness. Connection/fallback cannot masquerade as native evidence.
* Native translation quotes subprocess arguments, checks child status and WAV
  bounds, cleans temporary files on exceptions, initializes failure results and
  parses complete JSON. API translation uses the same boolean/text contract.
* The launcher serves built assets and API requests through the backend owner;
  its Python service binds loopback. Integration startup/cleanup is deterministic
  and database state is isolated. The dashboard permits explicit key entry.
* CMake exports C++20 and consistent feature flags, respects TFLite OFF, resolves
  external-prefix PortAudio paths, fixes SDK include paths and missing install
  inputs, and creates TGZ packages. Docker no longer masks build failure through
  a successful `tee` pipeline.

## 6. Potential risks investigated but not confirmed

Existing DSP noise/transient robustness and authenticated libsodium corruption
tests pass; no replacement algorithms or crypto protocol were justified.
No evidence supported redesigning projection geometry, beamforming or database
schema. Unknown profile keys remain forward-compatible. Optional model absence
is supported, but bridge presence never proves weights are loaded. Hardware
callback defenses were compiled and inspected; actual driver fault behavior has
not been experimentally established. Passing software tests cannot resolve
unmeasured physical assumptions or resource exhaustion.

## 7. Regression tests added

`tests/test_bedrock.cpp` declares 18 cases, with dependency-dependent selection
(18 Debug, 17 with PortAudio, 15 without translation). They cover native items
in the invariant table. `backend/test_bedrock.py` adds 27 cases including
parameterization; `backend/test_signaling.py` adds eight; version consistency
adds one. Four API smoke tests were rewritten as real assertions. Existing
backend tests remain enabled, yielding 54 total. Nine launcher functional checks
include asset MIME types and same-origin intent handling, plus a separate
negative startup invocation. `validate-package.sh` compiles/runs a separate
installed SDK consumer. Missing audio support has an explicit failure CTest.

## 8. Implementation scope and preserved architecture

The existing facade, pipeline stages, DSP math, calibration stages, SQLite
schema, API endpoints, React dashboard and launcher remain. No new service,
global state layer or replacement signal-processing algorithm was introduced.
The standard nlohmann JSON parser is private to optional native translation;
CMake uses an installed 3.11+ package or SHA256-pinned upstream 3.11.3 archive.
It does not leak JSON types or a JSON dependency into the installed SDK API.
Its MIT license notice is included in translation-enabled SDK installations.
PCM16 conversion reuses instance buffers; callers must pre-size float output
to avoid its documented resize allocation and serialize instance use.

## 9. State and atomicity improvements

Native reinitialization and telemetry use candidate/validate/commit semantics.
Rejected full-pipeline frames leave monitoring/DSP state untouched. SQLite
transactions encompass identity creation and incoming peer/session insertion;
rollback covers failures. State updates return the authoritative persisted row.

Calling or ringing can connect, end or time out; calling can become ringing.
Connected can end. Ended and timeout are terminal. Same-state retries preserve
timestamps, and expiry applies only to pending sessions. Peer deletion can
retain historical session references by design; no incompatible schema migration
was invented. These local transactions do not atomically coordinate a remote
node. Profile writes report stream errors but do not guarantee atomic replacement
or durability under process interruption.

## 10. Trust, security and safety hardening

`APM_API_KEY` remains opt-in. When enabled, protected API calls require the
header; dashboard viewing grants nothing. `SIGNALING_WS_TOKEN` remains opt-in,
but both apps now use the same enforcement. Invalid/missing join credentials
and malformed signaling close with policy violation; unjoined/cross-room relays
cannot send. Sender identity is derived from membership, not payload.

These shared secrets do not provide individual authentication or per-room ACLs.
Open mode remains explicit legacy prototype behavior. Configure TLS, ingress
and ASGI trusted proxies for deployments. Native telemetry TCP is not a signed
evidence channel. Calibration's software validity flag is not physical approval.
Subprocess quoting prevents configuration injection, but scripts/interpreter,
model supply chain and the host remain trusted; temporary files are not a
hardened multi-user sandbox.

## 11. Cross-component contracts improved

One WebSocket hub now owns both entrypoints. SQLite owns returned session state.
The backend owns dashboard assets and API routing; the launcher proxies them.
Native and Python translation accept actual JSON boolean success and nonempty
text. Native readiness means interpreter/bridge availability, not successful
inference. Monitoring distinguishes valid native evidence from offline fallback.
Compiled, API, UI/launcher, installer and citation versions are checked together.

## 12. CI as enforcement

CI executes native Debug/Release on Linux and macOS compiler matrices, a minimal
optional-dependency build, all backend tests, UI build, functional launcher checks,
deliberate startup failure and an installed SDK consumer/package. CTest errors
on zero tests; optimized test targets retain assertions. Sanitizers receive real
compiler/link flags, and UBSan halts on a finding. Coverage test failures propagate.
Native artifacts have unique matrix names. Release packaging depends on tests;
Docker publishing waits for successful checks and uses the actual Dockerfile.

Existing static analysis, benchmark and optional Doxygen generation are still
informational: clang-tidy failure is not gating, no benchmark source/Doxyfile is
present. They are not claimed as proven guarantees. Workflow syntax was checked
locally with actionlint; hosted jobs have not been run from this workspace.

## 13. Related repositories and external dependencies

No accessible related project supplied a separate trust or integration layer
that could be verified. Actual local adapters, subprocess bridge and third-party
library usage were inspected. Optional FFTW, libsodium and PortAudio were tested
with packages verified through signed Debian metadata; nlohmann JSON is hash
pinned. Wake-word/OEM/ASR compatibility and third-party services were not proven
by similarly named interfaces or historical documentation.

## 14. Version decision and compatibility

11.0.0 is the next major release after 10.1.0. The project claims Semantic
Versioning; there are real incompatible public contracts, not merely a milestone.
Native `get_session`/`get_active_session` return `std::optional<CallSession>`
snapshots rather than pointers into mutable storage. Replace explicit pointer
declarations with `auto`/optional and request a new snapshot for updated state.

API clients must provide the configured key rather than rely on a page-issued
cookie. Invalid terminal/stale transitions, malformed calibration/configuration,
non-normalized full-pipeline frames and malformed translation evidence are now
rejected because they contradict the existing domain/state/trust contracts.
Missing audio support no longer reports operational capture. Sound public audio
behavior and the original component architecture are retained.

## 15. Version metadata updated

CMake/generated config, native CLI and console, API metadata, Python control
tools, UI and launcher manifests/root lockfile records, rebuilt dashboard assets,
installer definition, citation, setup/user scripts and current documentation now
identify 11.0.0. Version tests compare authoritative declarations. Historical
10.x release notes and earlier feature descriptions are preserved; IPv4 addresses
and dependency versions are not application-version declarations.

## 16. Documentation changes

This report records contracts, compatibility and evidence. README links it and
identifies the current release. CHANGELOG adds an entry without rewriting history.
Backend and operational docs explain credentials, state transitions, database
configuration, evidence and proxy assumptions. The manifest accurately describes
Python in the existing Docker runtime. Historical validation remains available,

## 18. Known limitations

Docker build was attempted twice, including host networking/proxy forwarding.
The build container could not resolve package repositories. No image/package
installation result is claimed for Docker; signatures and TLS were not bypassed.
Windows and macOS installers/builds were not locally executed. The Windows
installer and user setup script reference `apm-headphone` binaries and assets
not produced by this native build, so metadata consistency does not prove
installer completeness. TFLite,
actual Whisper/NLLB inference, GPU and external-provider success were not tested.

Legacy `src/io/wav_io.cpp`, the alternative translation implementation and
`tests/test_main.cpp` are outside the authoritative build and were identified
as unvalidated. They were not silently registered against incompatible/missing
headers. No release was uploaded and no hosted CI result is claimed.

## 19. Remaining architectural risks

The complete pipeline waits for translation and cannot be certified real time.
Mutable profile/calibration access and native lifecycle/configuration callbacks
require caller coordination; serialization is not a universal concurrency proof.
UDP signaling logs received packets and has no complete authenticated remote
state machine. Shared secrets and arbitrary WebSocket room names are insufficient
for tenant isolation. SQLite state changes are local, not distributed transactions.
Interrupted profile/file writes and filesystem fault injection remain unproven.
Translation subprocess execution has no bounded inference deadline. Resource
exhaustion, long-duration drift and overload need deployment-specific envelopes.
Desktop timing tests and mock estimates do not establish wearable power/latency.

## 20. Real-world validation requirements

Validate actual microphone geometry, gains, clock drift, dropout, echo paths,
speaker feedback, clipping protection, acoustic exposure and failure recovery on
target hardware. Measure end-to-end latency, power and thermal behavior under
load; validate transcript quality and downstream wake-word/ASR integration with
actual models. Exercise driver faults, interruption, network partitions and
deployment authorization/TLS. Conduct domain-specific safety review and any
required certification separately. Software correctness, simulation, integration,
hardware validation and production approval remain distinct evidence levels.
